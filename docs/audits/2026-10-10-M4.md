# Ship audit — 2026-10-10 — M4 launch prep (M4a scene + M3 push/sync + M4b metrics)

**Verdict: SHIP AFTER BLOCKERS**

**Not checked:**
- **Real devices:** push delivery on Android Chrome and an installed iOS PWA, 12 avatars at ≥45 fps on a mid-range Android, two devices showing the same sync phase within 1 s. All are builder checks.
- **Realtime private-channel policies on the live project:** the local stack has no Realtime.
- **`web-design-guidelines` full pass:** not run this round. Only the 320px and reduced-motion spot checks below were done.
- **Network-request recording of a full session:** not re-run. The CSP still limits `connect-src` to self plus Supabase.
- **`supply-chain-risk-auditor` full pass:** only `pnpm audit --prod` was run, and it found nothing. The only new dependencies are `three@0.186.1` and `@react-three/fiber@9.8.1`; both are mainstream and were published more than 2 weeks ago.

**How:**
- **Mechanical:** typecheck, lint, 125 unit tests, build, 168 pgTAP assertions, 68 e2e tests, `deno check` and `pnpm audit`.
- **Review passes:** three independent ones (spec compliance, sharp edges, and a security review of `00d178e..HEAD`), plus database queries.

## Blockers

1. **One user can stop `tick()` for everyone.**
   - **Evidence:** `private.wants_push` casts `(settings -> 'notify' ->> kind)::boolean` (`supabase/migrations/20261010000000_m3_push_sync.sql:58-62`). `profiles.settings` is client-writable (`m1_core.sql:96`). `select ('maybe')::boolean` → `ERROR: invalid input syntax for type boolean`.
   - **Why it matters:** set `notify.phase_end = "x"`, save any FCM-shaped subscription, and start a pomodoro. From then on every tick raises at that session and the whole transaction rolls back every 10 s. For every user:
     - no sessions finish, and the 4h cap and check-ins stop;
     - no pushes or emails go out;
     - pending-consent accounts of minors are never deleted.
   - **Fix:** compare as JSON (`<> 'false'::jsonb`) instead of casting; give each tick step its own exception block, so one bad row can't stall the rest; add a pgTAP regression test.

2. **The "room is active" 2-hour limit stops working once a push is sent.**
   - **Evidence:** the trigger dedupes on `payload ->> 'room_id'` (`m3:118-121`), but `markSent` clears the payload to `{}` (`supabase/functions/push/index.ts:26`). The pgTAP test only checked rows that were still unsent.
   - **Why it matters:** a member can loop `start_session` (it has no rate limit) and push "X just started studying" to every opted-in minor about every 10 s. This is a harassment vector and also floods the queue. It also fails the M3 acceptance criterion.
   - **Fix:** keep `room_id` in a real column; dedupe on `(user_id, kind, room_id, created_at)`; rate-limit `start_session`; test the "sent, then started again" case.

3. **One bad subscription stalls the whole queue, parental-consent emails included.**
   - **Evidence:** in `push/index.ts:81-97,129-136`, neither `buildPushRequest` (`importKey` throws on a regex-valid but invalid P-256 key) nor `fetch` (DNS failure on an allowlisted host) is caught. The function returns 500, and rows are taken `order by id limit 50`, so the poisoned row blocks everything behind it for 10–30 minutes. It can be re-poisoned with each session.
   - **Fix:** try/catch around each row and each subscription; delete subscriptions whose keys don't decode; validate key length and the uncompressed-point prefix in `save_push_subscription`; give `fetch` a timeout and `redirect: 'manual'`.

## High

4. **Sign-out can hang forever.** `navigator.serviceWorker.ready` never resolves without a registered service worker (dev builds, failed registration), and `signOut` awaits it (`src/stores/push.ts:20`, `src/stores/auth.ts`). **Fix:** race it against a timeout, or use `getRegistration()`.

5. **A shared device keeps the previous account's subscription.**
   - **Evidence:** the endpoint is re-bound only on explicit sign-out (`src/stores/push.ts`). If account B signs in after A's session expired, the device is "subscribed", so B is never asked. The server still sends A's pushes there, including A's room names and friends' names.
   - **Fix:** remember the uid the device subscribed for; when it differs from the signed-in uid, re-save, so the endpoint moves to the current account.

6. **A missing VAPID key blocks consent emails and wakes the function every 10 s.**
   - **Evidence:** when the keys aren't set, push rows are skipped with `continue` before the stale check (`push/index.ts:133`). They stay unsent: `dispatch_queue` fires every tick, and after 50 rows, consent emails are never reached.
   - **Fix:** drop stale rows before checking the keys; when the keys are missing, retire push rows instead of leaving them queued.

7. **Any member can forge a `removed` broadcast and kick others out of the room screen.**
   - **Evidence:** `useRoomChannel.ts:93` trusts `{event:'removed', user_id}` from any sender. The Realtime policy lets members broadcast any event name. Membership is unchanged, but the victim sees "You were removed" and is sent home.
   - **Fix:** on `removed`, confirm by refetching `room_info`; only a `not_a_member` error counts.

## Medium

8. **The same row can be sent twice.** The function reads unsent rows without claiming them (`push/index.ts:118-124`), so overlapping invocations can repeat pushes and consent emails. **Fix:** claim rows atomically with a `claim_notifications` RPC (`for update skip locked`, push `send_after` forward).
9. **Gaps on the privacy page** (`src/features/privacy/PrivacyPage.tsx`):
   - It doesn't mention the timezone, settings, IP-derived rate-limit keys (`private.rate_limits`, purged after 1 day), or that a parent's email is kept in plain text until they decide.
   - It gives no retention for the queue (7 days).
   - Its strings aren't in `copy.ts`, which CLAUDE.md requires.
   - **Fix:** add the lines and move the text into `copy.ts`.
10. **The mini profile lacks the status line and this-week minutes** that §5.3 requires (`MemberSheet.tsx:84-122`). **Fix:** pass the live status line and the week leaderboard seconds into the sheet.
11. **The avatar check allows unknown keys:** up to about 2 KB of free text that every room member receives, a hidden text channel between minors (`m4_avatar_outfit.sql`). **Fix:** reject keys outside the known set.
12. **A spurious "Break time" push:** tick step 1 queues `phase_end` even if `finish_session` found the session already ended by a racing `end_session` (`m3:329-333`). **Fix:** queue it only when this call ended the session.

## Low / polish

- **`sw.ts` path check:** `sameOriginPath` accepts `/\evil.com`. It isn't exploitable today because the server builds the URL. **Fix:** check the parsed URL's origin.
- **Shared-secret comparison:** `x-push-secret` is compared with `!==`. Use a constant-time compare.
- **VAPID subject:** it silently defaults to `mailto:hello@example.com`. It should fail closed.
- **Nudges in shared focus:** they are muted only on the sender's side. Also drop received nudges during shared focus.
- **Profile toggles:** Profile has no per-room "room is active" toggles; they live in each room's ⋯ menu. Record this in a decision.
- **Home rank:** room cards don't show "your rank this week" (§5.2).
- **Event props outside §12:** `session_started.sync`, `app_open.standalone` and `signup.consent` (no free text). Record them in a decision.
- **`log_event` forgery:** it lets a client forge `reaction_sent`/`nudge_sent` counts. This is accepted (admin metrics don't use them).
- **Room title at 320px:** the name truncates heavily next to "Invite friends".
- **Room timezone:** an invalid room tz (set by the owner at creation) breaks that room's leaderboard. Validate it against `pg_timezone_names`.

## Verified

- ✅ Every public table has RLS. Policies that allow everything: only `consent_ages_read` (read-only reference data).
- ✅ Every security definer function pins `search_path`.
- ✅ Anon-executable functions are exactly `consent_decide, consent_view, health, preview_room, server_time` (pgTAP pins this).
- ✅ Private functions executable by `authenticated`: only `am_member`, `am_member_topic`, `valid_avatar` (needed by RLS and checks).
- ✅ Client write grants: only `profiles.{avatar, display_name, settings, tz}`. Sessions, membership, queue and subscriptions are written through RPCs only.
- ✅ The push endpoint allowlist is anchored (host followed by `/`); userinfo, port and lookalike-host bypasses fail.
- ✅ RFC 8291/8292 web push: labels, HKDF, header layout, a fresh key and salt per message, JWT aud/exp/sub. Tests decrypt the output the way a browser does.
- ✅ No secrets in `dist/` or `src/`; history contains only the grep pattern itself; only `VITE_` vars reach the client.
- ✅ CSP and security headers are unchanged and still strict; CI permissions are `contents: read`.
- ✅ No `dangerouslySetInnerHTML`. Names in 3D labels and notifications are plain text. Avatar colors are regex-checked hex.
- ✅ `admin_metrics`: admin-only, admins excluded, aggregates only, `p_weeks` clamped. The CSV export neutralises formulas.
- ✅ Sync pomodoro: the server sets the plan, there is no stopwatch, and joins are refused during breaks or with <60 s left. The SQL and TS maths share test vectors.
- ✅ Personal room scene uses 0 KB of models; the WebGL fallback works (e2e); reduced motion stops scene animation.
- ✅ The 320px layout has no horizontal overflow on Room, My Room or Profile.
- ✅ Export includes push devices (host only) and `notify_active`. Account deletion cascades to subscriptions and the queue.
- ✅ Pending users can't save subscriptions (`active_uid`) but can delete them.
- ✅ Sign-out deletes this device's subscription (when the service worker is ready, see #4).
