# Ship audit — 2026-10-09 — M2 (rooms, live state, safety, consent, themes)

Verdict: **SHIP AFTER BUILDER CHECKS** for the friendly alpha (2–3 trusted friends). The code side has no blockers. The items under "Not checked" need the hosted project.
Not checked (needs the hosted project or real devices):
- **Realtime private-channel policies** (`realtime.messages`): the local stack can't run Realtime. They're created conditionally and need a live test with two accounts.
- **The consent email end to end:** Resend plus a verified sender domain (still open, SPEC §17).
- **`supabase test db` on CI:** passes on GitHub. Locally `scripts/db-test.sh` runs the same files.

## Blockers
None.

## High
- **Fixed in this pass:** six M1 RPCs were executable by `anon` (Supabase's default grant). All six still required a user, so they weren't exploitable. The grant is revoked, and a pgTAP check pins the anon-callable list to the five public-page functions.

## Medium
- **The invite preview shows display names and avatars of who is studying** to anyone with the link. This is intended (SPEC §5.1) and stated on `/privacy`; the codes are 40-bit and rate-limited.
- **Reactions and nudges are rate-limited client-side only.** A modified client could spam its own room. Mitigations: only members can send (Realtime policy), recipients rate-limit what they show, and owners can remove people.
- **Blocking hides reactions, nudges and toasts from the blocked person.** A blocked roommate is still visible on desks and leaderboards (shared room fairness). Documented here so the behavior isn't a surprise.

## Low / polish
- The blocked-people list shows a short id instead of a name, because blocked users' profiles aren't readable. Add a small RPC returning their display names when it matters.
- The Supabase JS bundle keeps the precache at ~800 KB. Revisit in the M4 performance pass.

## Verified
- ✅ RLS on every public table; no write grants except 4 profile columns (catalog queries).
- ✅ Every security definer function pins `search_path`.
- ✅ anon can execute only `health, server_time, preview_room, consent_view, consent_decide` (pgTAP).
- ✅ Room isolation: outsiders can't see rooms, live state, leaderboards or study in them; removed members can't rejoin; old invite links die (pgTAP).
- ✅ Roles: members can't moderate; mods can't hand out roles; owners must transfer before leaving; deleting an account passes rooms to the longest-standing mod (pgTAP).
- ✅ Voids need a reason, leave leaderboards, are visible to the member; 3 voids in 7 days auto-report (pgTAP).
- ✅ Profanity filter on every write path (triggers), with leetspeak, without false positives on words like "class"/"assignment" (pgTAP + unit tests, JSON↔SQL in sync).
- ✅ Consent: hashed tokens, plain parent email cleared after the decision, resends throttled (max 3), grant/withdraw/expiry paths (pgTAP).
- ✅ Delete account leaves no sessions; export returns profile, rooms, sessions, blocks, reports (pgTAP).
